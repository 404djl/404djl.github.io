第 1 节：操作系统概述与实验环境搭建

学习目标：理解操作系统的角色与核心抽象，掌握 xv6 项目结构，搭建可运行的实验环境。

预计用时：2-3 小时

前置要求：C 语言基础、Linux 命令行基本操作

一、理论：操作系统的角色

1.1 什么是操作系统？

操作系统是介于硬件和应用程序之间的软件层。它有两个核心职责：

  1. 资源管理：CPU 时间、内存、磁盘、I/O 设备等硬件资源由多个程序共享，操作系统负责分配和调度
  2. 抽象封装：隐藏硬件细节，为应用程序提供统一、简洁的接口（系统调用）
┌──────────────────────────────────────┐
│          应用程序 (Application)       │
├──────────────────────────────────────┤  ← 系统调用接口 (ecall)
│            操 作 系 统               │
│  ┌──────────┬──────────┬──────────┐  │
│  │ 进程管理  │ 内存管理  │ 文件系统 │  │
│  └──────────┴──────────┴──────────┘  │
├──────────────────────────────────────┤
│          硬件 (Hardware)             │
│    CPU    内存    磁盘    I/O 设备    │
└──────────────────────────────────────┘

1.2 操作系统的三大核心抽象

操作系统的精髓在于用简单的抽象来管理复杂的硬件：

硬件资源 OS 抽象 含义
CPU 进程 (Process) 每个程序以为自己独占 CPU
物理内存 虚拟内存 (Virtual Memory) 每个程序以为自己拥有完整的地址空间
磁盘 文件 (File) 持久化的命名数据，无需关心磁盘块号

为什么需要这些抽象？

  • 隔离性：一个程序崩溃不会影响其他程序
  • 多路复用：多个程序可以”同时”运行
  • 易用性：程序员用 read()/write() 操作文件，无需知道磁盘驱动协议

1.3 内核态 vs 用户态

CPU 提供特权级机制来实现隔离：

特权级高 ─────────────────────────── 特权级低
    │                                    │
    ▼                                    ▼
 Machine (M)    Supervisor (S)       User (U)
  固件/BIOS       操作系统内核       应用程序
  全部权限       大部分权限        受限权限
  • 用户态 (User mode)：应用程序运行在此模式，不能直接访问硬件、不能修改页表
  • **内核态 (Supervisor mode)**：操作系统内核运行在此模式，可以执行特权指令
  • 切换方式：用户程序通过 ecall 指令（系统调用）进入内核态，内核通过 sret 指令返回用户态

关键问题：如果没有特权级隔离会怎样？

任何程序都可以直接操作硬件，一个恶意或有 bug 的程序可以覆盖其他程序的内存、破坏磁盘数据。

1.4 xv6 的设计哲学

xv6 采用宏内核 (Monolithic Kernel) 架构：

  • 整个操作系统运行在内核态：进程管理、内存管理、文件系统、设备驱动都在一个地址空间
  • 优点：内核内部调用效率高，模块间可以直接调用函数
  • 缺点：一个模块的 bug 可能导致整个内核崩溃
  • **对比微内核 (Microkernel)**：只把最小的功能放在内核，驱动和文件系统运行在用户态

xv6 的定位：

  • 教学用操作系统，源于 Unix v6（1975 年）
  • 总代码量约 8000 行 C + 几百行汇编
  • 实现了 Unix 的核心功能：进程、虚拟内存、文件系统、管道、设备驱动
  • 每个模块都小到可以完整阅读和理解

2.2 Makefile 关键解读

Makefile 是理解项目编译流程的关键，下面拆解最重要的部分：

工具链配置（第 44-60 行）：

# xv6 运行在 RISC-V 上，需要交叉编译工具链
TOOLPREFIX := riscv64-unknown-elf-    # 或 riscv64-linux-gnu-
CC = $(TOOLPREFIX)gcc                 # 交叉编译器
LD = $(TOOLPREFIX)ld                  # 链接器
OBJDUMP = $(TOOLPREFIX)objdump        # 反汇编工具

编译选项（第 70-81 行）：

CFLAGS = -Wall -Werror -O -fno-omit-frame-pointer -ggdb
# -Wall -Werror    : 所有警告视为错误（严格编码）
# -O               : 基本优化
# -fno-omit-frame-pointer : 保留帧指针（方便调试和 backtrace）
# -ggdb            : 生成 GDB 调试信息
# -mcmodel=medany  : RISC-V 代码模型，支持高地址
# -ffreestanding   : 独立环境（没有标准库）
# -nostdlib        : 不链接标准库

内核构建（第 93-96 行）：

$K/kernel: $(OBJS) $K/kernel.ld $U/initcode
    $(LD) -T $K/kernel.ld -o $K/kernel $(OBJS)     # 链接所有 .o 文件
    $(OBJDUMP) -S $K/kernel > $K/kernel.asm         # 生成反汇编（调试用）
    $(OBJDUMP) -t $K/kernel > $K/kernel.sym         # 生成符号表

用户程序构建（第 107-112 行）：

ULIB = $U/ulib.o $U/usys.o $U/printf.o $U/umalloc.o   # 用户库

_%: %.o $(ULIB)                                         # 模式规则
    $(LD) -N -e main -Ttext 0 -o $@ $^                  # 入口是 main，从地址 0 开始

每个用户程序都链接同一套用户库（ulib, usys, printf, umalloc）。

QEMU 启动参数（第 200-206 行）：

CPUS := 3                                            # 默认 3 个 CPU 核心

QEMUOPTS = -machine virt       # RISC-V virt 虚拟平台
    -bios none                  # 不使用 BIOS（直接跳到内核）
    -kernel $K/kernel           # 内核 ELF 文件
    -m 128M                     # 128MB 物理内存
    -smp $(CPUS)                # 多核 CPU
    -nographic                  # 无图形界面（纯串口）
    -drive file=fs.img,...      # 虚拟磁盘
    -device virtio-blk-device   # Virtio 块设备

文件系统镜像（第 181-182 行）：

fs.img: mkfs/mkfs README $(UPROGS)
    mkfs/mkfs fs.img README $(UPROGS)    # 将 README 和所有用户程序打包进磁盘镜像

2.3 kernel/param.h：系统常量

这个小文件定义了 xv6 的”硬编码”限制：

#define NPROC        64   // 系统最多 64 个进程
#define NCPU          8   // 最多支持 8 个 CPU
#define NOFILE       16   // 每个进程最多打开 16 个文件
#define NFILE       100   // 系统全局最多 100 个打开文件
#define NINODE       50   // 内存中最多缓存 50 个 inode
#define NDEV         10   // 最多 10 种设备
#define ROOTDEV       1   // 根文件系统所在设备号
#define MAXARG       32   // exec() 最多 32 个参数
#define MAXOPBLOCKS  10   // 一次文件操作最多写 10 个块
#define LOGSIZE      30   // 日志区大小 = MAXOPBLOCKS * 3
#define NBUF         30   // 块缓存数量 = MAXOPBLOCKS * 3
#define FSSIZE     1000   // 文件系统总大小（1000 个块 ≈ 1MB）
#define MAXPATH     128   // 路径名最大长度

思考：这些常量都是编译时确定的，不能动态调整。真实操作系统（如 Linux）如何处理？

Linux 使用动态数据结构（如链表、哈希表、slab 分配器），没有固定上限。xv6 使用固定数组是为了简化实现。

2.4 kernel/types.h：基础类型定义

typedef unsigned int   uint;      // 32 位无符号整数
typedef unsigned short ushort;    // 16 位无符号整数
typedef unsigned char  uchar;     // 8 位无符号整数

typedef unsigned char  uint8;     // 显式宽度类型
typedef unsigned short uint16;
typedef unsigned int   uint32;
typedef unsigned long  uint64;    // RISC-V 64 位平台上 long = 64 位

typedef uint64 pde_t;             // 页目录/页表项类型（64 位）

为什么不用 <stdint.h>？

xv6 使用 -ffreestanding 编译，即”独立环境”——没有 C 标准库。所以必须自己定义这些类型。

2.5 kernel/defs.h：内核函数声明汇总

这个文件是整个内核的”目录”，按模块组织了所有公共函数的声明。它的结构本身就展示了 xv6 的模块划分：

// fs.c        — 文件系统（inode、目录、路径解析）
// kalloc.c    — 物理页分配
// log.c       — 日志层
// pipe.c      — 管道

// proc.c      — 进程管理
// spinlock.c  — 自旋锁

// trap.c      — Trap 处理
// uart.c      — UART 串口驱动
// vm.c        — 虚拟内存
// plic.c      — 中断控制器
// virtio_disk.c — 磁盘驱动

共 187 行，声明了约 80 个函数。每个函数在后续课程中都会详细讲解。

2.6 kernel/main.c：内核初始化入口

这是理解 xv6 启动的关键文件，仅 45 行：

volatile static int started = 0;       // 多核同步标志

void main() {
    if(cpuid() == 0){                  // 只有 CPU 0 做完整初始化
        consoleinit();                 // 初始化控制台
        printfinit();                  // 初始化 printf 锁
        printf("xv6 kernel is booting\n");
        kinit();                       // 物理页分配器
        kvminit();                     // 创建内核页表
        kvminithart();                 // 开启分页
        procinit();                    // 进程表
        trapinit();                    // Trap 向量
        trapinithart();                // 安装内核 trap 向量
        plicinit();                    // 初始化中断控制器
        plicinithart();                // 使能设备中断
        binit();                       // 块缓存
        iinit();                       // inode 缓存
        fileinit();                    // 文件表
        virtio_disk_init();            // 磁盘驱动
        userinit();                    // 创建第一个用户进程
        __sync_synchronize();          // 内存屏障
        started = 1;                   // 通知其他 CPU
    } else {
        while(started == 0)            // 其他 CPU 等待 CPU 0
            ;
        __sync_synchronize();
        kvminithart();                 // 开启分页
        trapinithart();                // 安装 trap 向量
        plicinithart();                // 使能中断
    }
    scheduler();                       // 进入调度循环（永不返回）
}

关键洞察：

  • 初始化有严格的顺序依赖（如必须先初始化内存分配器，才能创建页表）
  • 只有 CPU 0 做”重量级”初始化，其他 CPU 只做最基本的硬件初始化
  • scheduler() 是一个无限循环，main() 永远不会返回

三、源码精读：用户程序的结构

3.1 用户程序的组成

每个 xv6 用户程序都包含三个部分：

┌────────────────────────────────────────────────┐
│              用户程序 (如 echo.c)               │
├────────────────────────────────────────────────┤
│  #include "kernel/types.h"    ← 基础类型       │
│  #include "kernel/stat.h"     ← 文件状态结构    │
│  #include "user/user.h"       ← 系统调用 + 库   │
├────────────────────────────────────────────────┤
│  int main(int argc, char *argv[]) { ... }      │
│  exit(0);        ← 必须调用 exit()，不能 return │
└────────────────────────────────────────────────┘

重要区别：在普通 C 程序中，main() 返回后 C 运行时库会调用 exit()。xv6 没有 C 运行时，所以**必须显式调用 exit()**。

3.2 user/echo.c 精读（19 行）

#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

int
main(int argc, char *argv[])
{
  int i;

  for(i = 1; i < argc; i++){       // 跳过 argv[0]（程序名）
    write(1, argv[i], strlen(argv[i]));  // 写到 stdout（fd=1）
    if(i + 1 < argc){
      write(1, " ", 1);            // 参数之间用空格分隔
    } else {
      write(1, "\n", 1);           // 最后一个参数后换行
    }
  }
  exit(0);                          // 退出进程
}

学习要点：

  1. write(1, buf, n) 是系统调用：第一个参数 1 是文件描述符（stdout）
  2. 没有用 printf()，直接用 write() ——这展示了最底层的输出方式
  3. strlen() 来自用户库 ulib.c，不是内核函数

文件描述符约定（Unix 通用）：

fd 含义
0 stdin（标准输入）
1 stdout（标准输出）
2 stderr（标准错误）

3.3 user/cat.c 精读（43 行）

#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

char buf[512];                     // 全局缓冲区（512 字节）

void
cat(int fd)
{
  int n;
  while((n = read(fd, buf, sizeof(buf))) > 0) {  // 循环读取
    if (write(1, buf, n) != n) {                   // 写到 stdout
      fprintf(2, "cat: write error\n");            // 错误信息写到 stderr
      exit(1);
    }
  }
  if(n < 0){
    fprintf(2, "cat: read error\n");
    exit(1);
  }
}

int
main(int argc, char *argv[])
{
  int fd, i;

  if(argc <= 1){
    cat(0);                        // 没有参数时，从 stdin 读取
    exit(0);
  }

  for(i = 1; i < argc; i++){
    if((fd = open(argv[i], 0)) < 0){    // 打开文件（只读模式）
      fprintf(2, "cat: cannot open %s\n", argv[i]);
      exit(1);
    }
    cat(fd);                       // 输出文件内容
    close(fd);                     // 关闭文件
  }
  exit(0);
}

学习要点：

  1. read() 的返回值：正数 = 读到的字节数，0 = 到达文件末尾（EOF），负数 = 错误
  2. open() 的返回值：成功返回文件描述符（非负整数），失败返回 -1
  3. 循环读写模式：while(read(...) > 0) { write(...); } 是 Unix I/O 的经典模式
  4. 资源管理：打开了文件就要 close()，类似于分配内存要 free()

这个文件是用户程序的”API 参考”：

系统调用 vs 库函数：

  • 系统调用：需要通过 ecall 陷入内核（有上下文切换开销）
  • 库函数：在用户空间执行，不进入内核（如 strlen, strcmp）
  • 有些库函数内部调用系统调用（如 printf() 最终调用 write()）

3.5 系统调用的实现机制（预览）

当用户程序调用 write(1, "hello", 5) 时，实际执行的是 usys.S 中的汇编 stub：

# user/usys.pl 生成的汇编代码（每个系统调用都是这个模式）：
sub entry {
    my $name = shift;
    print ".global $name\n";      # 导出符号
    print "${name}:\n";           # 函数标签
    print " li a7, SYS_${name}\n";  # 将系统调用号放入 a7 寄存器
    print " ecall\n";            # 触发 trap，进入内核
    print " ret\n";              # 从内核返回后，继续执行
}

以 write 为例，生成的汇编是：

.global write
write:
  li a7, SYS_write    # a7 = 16（write 的系统调用号）
  ecall               # 陷入内核
  ret                  # 内核返回后，a0 中是返回值

调用约定：

  • 参数通过寄存器传递：a0, a1, a2, …
  • 系统调用号放在 a7
  • 返回值在 a0

这个机制将在第 10 节详细讲解。

3.6 user/init.c：第一个用户进程

这是整个用户空间的”创世”程序：

int main(void)
{
  int pid, wpid;

  // 1. 打开控制台设备作为 stdin (fd 0)
  if(open("console", O_RDWR) < 0){
    mknod("console", CONSOLE, 0);   // 如果不存在，先创建设备文件
    open("console", O_RDWR);
  }
  dup(0);  // 复制 fd 0 → fd 1 (stdout)
  dup(0);  // 复制 fd 0 → fd 2 (stderr)

  // 2. 无限循环：启动 shell，shell 退出后重新启动
  for(;;){
    printf("init: starting sh\n");
    pid = fork();                    // 创建子进程
    if(pid == 0){
      exec("sh", argv);             // 子进程执行 shell
      printf("init: exec sh failed\n");
      exit(1);
    }

    for(;;){
      wpid = wait((int *) 0);       // 等待任何子进程退出
      if(wpid == pid){
        break;                       // shell 退出了，跳出内层循环重启
      } else if(wpid < 0){
        printf("init: wait returned an error\n");
        exit(1);
      }
      // 收到其他孤儿进程退出的通知，忽略
    }
  }
}

关键知识点：

  1. init 进程是所有用户进程的祖先（PID = 1）
  2. 它负责建立 fd 0/1/2（stdin/stdout/stderr），后续 fork() 出的子进程会继承
  3. init 永远不会退出——如果 shell 退出了，init 会重新启动一个新 shell
  4. init 还负责收割孤儿进程（父进程已退出的进程）

// 修改后的 echo，输出格式：[1]hello [2]world
int main(int argc, char *argv[])
{
  int i;
  char num[4];  // 用于存储编号字符

  for(i = 1; i < argc; i++){
    // 输出编号
    write(1, "[", 1);
    num[0] = '0' + i;  // 简单处理，只支持个位数
    write(1, num, 1);
    write(1, "]", 1);

    write(1, argv[i], strlen(argv[i]));
    if(i + 1 < argc){
      write(1, " ", 1);
    } else {
      write(1, "\n", 1);
    }
  }
  exit(0);
}

五、思考题

  1. xv6 的 cat 使用 512 字节的缓冲区。如果改成每次只读 1 个字节（read(fd, buf, 1)），功能上有什么区别？性能上呢？

    功能完全相同。但性能会差很多——每次 read() 都是一次系统调用，需要用户态→内核态→用户态的切换。512 字节的缓冲区将系统调用次数减少到了 1/512。

  2. user/user.h 中声明了 21 个系统调用。Linux 有多少个系统调用？这说明了什么？

    Linux x86_64 有约 300+ 个系统调用。xv6 只实现了 Unix 最核心的接口。这说明 xv6 是一个极简的教学系统，但它的 21 个系统调用已经足以支持 shell、管道、文件操作等核心功能。

  3. 为什么 init.c 要先 open("console")，再用 dup(0) 来设置 stdout 和 stderr？直接 open 三次可以吗？

    可以直接 open 三次，效果相同。但 dup(0) 的写法更清楚地表达了意图：stdout 和 stderr 指向与 stdin 同一个文件（控制台设备）。用 dup() 它们共享同一个文件偏移量（虽然对设备文件来说这不太重要）。

  4. param.h 定义 NPROC=64。如果同时运行超过 64 个进程会怎样？

    fork() 系统调用会在 allocproc() 中找不到空闲的进程槽位，返回 -1（失败）。可以在 xv6 中运行 user/forktest.c 来验证这个限制。

六、本节小结

概念 要点
OS 的角色 资源管理 + 抽象封装
三大抽象 进程（CPU）、虚拟内存（内存）、文件（磁盘）
特权级 内核态（S-mode）可以做任何事，用户态（U-mode）受限
宏内核 所有 OS 功能在一个地址空间，xv6 采用此架构
项目结构 kernel/（内核）、user/（用户程序）、mkfs/（文件系统工具）
用户程序模式 包含头文件 → main() → 系统调用 → exit()
编译流程 交叉编译 → 链接 → 打包 fs.img → QEMU 启动
