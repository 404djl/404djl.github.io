第 9 节：Trap 机制（用户态）

学习目标：深入理解用户态 trap 的完整处理流程——从 ecall 硬件触发到 sret 硬件返回，掌握 TRAMPOLINE 的精妙设计，理解 sscratch、sepc、scause 等 CSR 寄存器的精确语义。

预计用时：3-4 小时

前置要求：完成第 2 节（RISC-V CSR 基础）、第 5 节（页表与地址空间）、第 8 节（进程调度）

一、理论：Trap 是什么？

1.1 Trap 的三种来源

“Trap”是 RISC-V 中所有打断正常执行流、转入特权级处理的事件的统称：

类型 触发方式 RISC-V 术语 scause 最高位 典型例子
系统调用 用户态执行 ecall 指令 Exception 0（异常） read(), write(), fork()
异常 CPU 执行非法操作 Exception 0（异常） 非法地址访问、非法指令、页错误
中断 外部设备或计时器触发 Interrupt 1（中断） 时钟、UART 输入、磁盘完成

scause 寄存器的最高位（第 63 位）区分中断（1）和异常（0），低位编码具体原因：

scause 常见值（xv6 中）：

  中断（最高位=1）：
    0x8000000000000001  软件中断（S-mode，来自 timervec）
    0x8000000000000005  时钟中断（S-mode，理论上，xv6 用软件中断转发）
    0x8000000000000009  外部中断（S-mode，PLIC 发出）

  异常（最高位=0）：
    2   非法指令
    5   Load 地址对齐错误
    7   Store 地址对齐错误
    8   用户态 ecall（系统调用！）
    12  Instruction Page Fault（取指页错误）
    13  Load Page Fault（读访问页错误）
    15  Store Page Fault（写访问页错误）

1.2 用户态 Trap 的难题

用户态发生 trap 时，CPU 需要从用户态切换到内核态，这看起来很简单，但有一个致命难题：

需要切换页表（用户页表 → 内核页表），但切换页表的代码本身必须在两张表中都能访问！

推导出来的约束：

  • trap 入口代码在用户页表中映射
  • trap 入口代码在内核页表中也必须映射到相同的虚拟地址
  • 否则，切换 satp 那条指令执行完，PC+4 在新页表中找不到映射，立刻 Page Fault

xv6 的解决方案——TRAMPOLINE 页：

用户页表：
  [代码][数据][栈][堆]     ...（低地址区域）
  TRAPFRAME: TRAMPOLINE-PGSIZE  ← 每进程私有，存放 trapframe
  TRAMPOLINE: MAXVA-PGSIZE      ← 映射到 trampoline.S 的物理页

内核页表：
  [内核代码][内核数据][直接映射区域]...
  内核栈（KSTACK）
  TRAMPOLINE: MAXVA-PGSIZE      ← 同一物理页，同一虚拟地址！

TRAMPOLINE = MAXVA - PGSIZE = 0x3FFFFF000（Sv39 最大虚拟地址减一页），在用户页表和内核页表中映射到完全相同的虚拟地址。切换 satp 前后，TRAMPOLINE 范围内的代码仍然可以执行——这就是”弹簧板”（trampoline）的含义。

1.3 关键 CSR 寄存器回顾

trap 处理要用到 5 个 S-mode CSR，理解它们是读懂源码的基础：

CSR 读写 内容 trap 中的作用
stvec 读写 trap 处理程序的入口地址 触发 trap 时 CPU 跳到这里
sepc 读写 导致 trap 的指令地址 保存”被打断的位置”，sret 返回这里
scause 只读 trap 类型编码 usertrap() 用它区分 syscall/中断/异常
sscratch 读写 暂存任意值（无特定语义） xv6 用来存 trapframe 地址（详见下文）
sstatus 读写 状态寄存器（SPP, SPIE, SIE 等位） SPP=0 表示从用户态来；sret 后的中断使能由 SPIE 决定

硬件在 trap 时自动做的事（不需要软件干预）：

  1. 将当前 PC 存入 sepc（对于 ecall，sepc = ecall 指令的地址）
  2. 将 trap 类型编码存入 scause
  3. 将 sstatus.SIE（当前中断使能位）复制到 sstatus.SPIE，然后清除 SIE（关闭中断）
  4. 将当前特权级存入 sstatus.SPP（0=User, 1=Supervisor）
  5. 切换特权级到 Supervisor
  6. 跳转到 stvec（不修改页表！）

硬件 sret 时自动做的事：

  1. 将 sstatus.SPIE 复制回 sstatus.SIE（恢复中断使能状态）
  2. sstatus.SPP 决定返回特权级（0=User）
  3. PC = sepc
  4. 切换到 sstatus.SPP 指定的特权级
  5. 不修改页表（需要软件在 sret 之前切换）

二、源码精读：kernel/trampoline.S（141 行）

trampoline.S 是两段纯汇编代码：uservec（进内核）和 userret（出内核）。它运行在最特殊的环境下——切换页表的前后。

2.1 uservec：用户态 → 内核态

以下是完整的 uservec 代码，加上每行的详细注释：

.globl uservec
uservec:
        # ── 此时的上下文 ──
        # 特权级：Supervisor（硬件 trap 时已切换）
        # 页表：用户页表（satp 尚未切换！）
        # PC：TRAMPOLINE 虚拟地址（用户/内核页表都有映射）
        # 所有寄存器：仍是用户态的值（没有任何寄存器可以"安全"使用）
        # sscratch：存放 TRAPFRAME 地址（由 usertrapret() 提前设置）

        # ① 原子交换 a0 和 sscratch
        # 之后：a0 = TRAPFRAME 地址，sscratch = 用户的 a0 原始值
        csrrw a0, sscratch, a0

        # ② 保存 31 个用户寄存器到 trapframe（a0 是第 32 个，后面单独处理）
        sd ra,   40(a0)   # trapframe 偏移 40   （注意：偏移 0-32 已被内核字段占用）
        sd sp,   48(a0)
        sd gp,   56(a0)
        sd tp,   64(a0)
        sd t0,   72(a0)
        sd t1,   80(a0)
        sd t2,   88(a0)
        sd s0,   96(a0)
        sd s1,  104(a0)
        # 跳过 a0（112），先保存 a1-a7
        sd a1,  120(a0)
        sd a2,  128(a0)
        sd a3,  136(a0)
        sd a4,  144(a0)
        sd a5,  152(a0)
        sd a6,  160(a0)
        sd a7,  168(a0)
        sd s2,  176(a0)
        sd s3,  184(a0)
        sd s4,  192(a0)
        sd s5,  200(a0)
        sd s6,  208(a0)
        sd s7,  216(a0)
        sd s8,  224(a0)
        sd s9,  232(a0)
        sd s10, 240(a0)
        sd s11, 248(a0)
        sd t3,  256(a0)
        sd t4,  264(a0)
        sd t5,  272(a0)
        sd t6,  280(a0)

        # ③ 保存用户的 a0（目前在 sscratch 中）
        csrr t0, sscratch
        sd t0, 112(a0)    # trapframe->a0 = 用户的 a0 原始值

        # ④ 从 trapframe 加载内核栈指针
        ld sp, 8(a0)      # sp = p->trapframe->kernel_sp（内核栈顶）

        # ⑤ 从 trapframe 加载 hartid 到 tp（cpuid() 用 tp 寄存器）
        ld tp, 32(a0)     # tp = p->trapframe->kernel_hartid

        # ⑥ 从 trapframe 加载 usertrap() 函数地址到 t0
        ld t0, 16(a0)     # t0 = p->trapframe->kernel_trap（= &usertrap）

        # ⑦ 从 trapframe 加载内核页表，切换 satp
        ld t1, 0(a0)      # t1 = p->trapframe->kernel_satp（内核页表的 satp 值）
        csrw satp, t1     # 切换到内核页表！
        sfence.vma zero, zero  # TLB 刷新（让新页表立即生效）

        # ── 此时 satp 已切换到内核页表 ──
        # a0 仍指向 TRAPFRAME 地址，但这个地址在内核页表中没有映射！
        # （TRAPFRAME 只映射在用户页表中）
        # 所以 a0 失效了——但我们不再需要它了（内核信息已经加载完毕）

        # ⑧ 跳转到 usertrap()
        jr t0              # PC = t0 = &usertrap
                           # 注意：这里用 jr（jump register），
                           # 不用 call，因为无需设置 ra（usertrap 不返回到这里）

csrrw a0, sscratch, a0 的精妙之处：

这是整个 trap 机制中最精妙的一条指令。csrrw 是”CSR Read-Write”：原子地将 a0 写入 sscratch，同时将 sscratch 的旧值读入 a0——这是一次原子交换。

执行前：a0 = 用户代码中断时的 a0 值（未知）
        sscratch = TRAPFRAME 地址（由 usertrapret() 预先设置）

执行 csrrw a0, sscratch, a0：原子地交换

执行后：a0 = TRAPFRAME 地址 ← 可以用来保存寄存器了！
        sscratch = 用户的 a0 原始值 ← 保存在这里，稍后写入 trapframe

为什么用 sscratch 而不是直接用某个寄存器？因为进入 uservec 时，所有 32 个通用寄存器都有用户态的值，不能直接使用任何一个来存放内核指针——否则就会破坏用户寄存器的值。sscratch 是唯一可以在不修改任何通用寄存器的前提下”交换”出一个值的地方。

sfence.vma zero, zero 的必要性：

切换 satp 后，TLB（转址旁路缓冲区）中缓存的旧翻译结果不能立即失效——CPU 可能还在用就的翻译访问内存。sfence.vma 刷新 TLB，确保后续所有内存访问都使用新页表翻译。少了这条指令，切换后可能读到旧页表表项对应的错误物理地址（数据损坏或安全漏洞）。

2.2 uservec 进入前的状态准备（usertrapret() 做的事）

uservec 在进入时假设 sscratch = TRAPFRAME，还假设 trapframe 中的 kernel_sp、kernel_satp、kernel_trap、kernel_hartid 字段都是有效的。这些值由谁来设置？答案是**上一次从内核返回用户态时的 usertrapret()**。

// kernel/trap.c
void
usertrapret(void)
{
  struct proc *p = myproc();

  // ① 关闭中断：即将修改 stvec，不能在此时响应中断
  intr_off();

  // ② 设置 stvec 指向 trampoline.S 的 uservec（用户态 trap 入口）
  // （此前 stvec 指向 kernelvec，因为在内核中）
  w_stvec(TRAMPOLINE + (uservec - trampoline));
  //      └─ uservec 在 TRAMPOLINE 页内的偏移 ─┘
  //         用相对偏移确保即使内核代码在不同地址加载也正确

  // ③ 将内核信息预先写入 trapframe，供下次 uservec 使用
  p->trapframe->kernel_satp = r_satp();           // 内核页表（当前 satp）
  p->trapframe->kernel_sp = p->kstack + PGSIZE;  // 内核栈顶（kstack 页的末尾）
  p->trapframe->kernel_trap = (uint64)usertrap;  // usertrap() 函数地址
  p->trapframe->kernel_hartid = r_tp();          // 当前 CPU 的 hartid

  // ④ 设置 sstatus：SPP=0（sret 返回用户态），SPIE=1（返回后开启中断）
  unsigned long x = r_sstatus();
  x &= ~SSTATUS_SPP;  // 清除 SPP（= 0 表示从用户态来，sret 返回用户态）
  x |= SSTATUS_SPIE;  // 设置 SPIE（sret 后 SIE = SPIE = 1，开启中断）
  w_sstatus(x);

  // ⑤ 设置 sepc = trapframe->epc（用户程序恢复时的 PC）
  w_sepc(p->trapframe->epc);

  // ⑥ 准备调用 userret（trampoline.S 的第二段汇编）
  uint64 satp = MAKE_SATP(p->pagetable);  // 用户页表的 satp 值

  // ⑦ 跳转到 trampoline.S 的 userret
  // 传入两个参数：a0 = TRAPFRAME 地址，a1 = 用户页表 satp
  uint64 fn = TRAMPOLINE + (userret - trampoline);
  ((void (*)(uint64, uint64))fn)(TRAPFRAME, satp);
  // 注意：userret 不会返回（sret 后进入用户态）
}

TRAMPOLINE + (uservec - trampoline) 的计算：

trampoline（C 符号）：trampoline.S 代码在内核 .text 中的虚拟地址（也是物理地址，因为直接映射）
uservec（C 符号）：uservec 标签在 .text 中的虚拟地址
uservec - trampoline：uservec 在 trampoline 页内的字节偏移（= 0，因为 uservec 就是第一个符号）
TRAMPOLINE + 偏移：在 TRAMPOLINE 虚拟页中的地址

这样，无论内核加载到什么物理地址，都能正确计算 TRAMPOLINE 页中 uservec 的虚拟地址。

2.3 userret：内核态 → 用户态

.globl userret
userret:
        # ── 此时的上下文 ──
        # 特权级：Supervisor
        # 页表：内核页表（satp 还没有切换）
        # 参数：a0 = TRAPFRAME 地址，a1 = 用户页表 satp 值

        # ① 切换到用户页表
        csrw satp, a1
        sfence.vma zero, zero
        # ── satp 已切换，现在使用用户页表 ──
        # TRAMPOLINE 在用户页表中仍然映射到相同虚拟地址，代码继续执行

        # ② 预先将用户的 a0 存入 sscratch（稍后 csrrw 取回）
        ld t0, 112(a0)    # t0 = trapframe->a0（用户的 a0 原始值）
        csrw sscratch, t0 # sscratch = 用户的 a0（为最后一步的 csrrw 准备）

        # ③ 恢复 31 个用户寄存器（除 a0 外，a0 在最后一步恢复）
        ld ra,   40(a0)
        ld sp,   48(a0)
        ld gp,   56(a0)
        ld tp,   64(a0)
        ld t0,   72(a0)
        ld t1,   80(a0)
        ld t2,   88(a0)
        ld s0,   96(a0)
        ld s1,  104(a0)
        # 跳过 a0（112）
        ld a1,  120(a0)
        ld a2,  128(a0)
        ld a3,  136(a0)
        ld a4,  144(a0)
        ld a5,  152(a0)
        ld a6,  160(a0)
        ld a7,  168(a0)
        ld s2,  176(a0)
        ld s3,  184(a0)
        ld s4,  192(a0)
        ld s5,  200(a0)
        ld s6,  208(a0)
        ld s7,  216(a0)
        ld s8,  224(a0)
        ld s9,  232(a0)
        ld s10, 240(a0)
        ld s11, 248(a0)
        ld t3,  256(a0)
        ld t4,  264(a0)
        ld t5,  272(a0)
        ld t6,  280(a0)

        # ④ 恢复 a0，同时将 TRAPFRAME 地址存回 sscratch（下次 uservec 用）
        csrrw a0, sscratch, a0
        # 执行后：a0 = 用户的 a0 原始值（从 sscratch 取出）
        #         sscratch = TRAPFRAME 地址（a0 的旧值，下次 uservec 需要）

        # ⑤ 返回用户态
        sret
        # 硬件执行：
        # PC = sepc（usertrapret 设置的用户 PC）
        # 特权级 = sstatus.SPP（被清为 0 = User）
        # sstatus.SIE = sstatus.SPIE（= 1，开启中断）

2.4 uservec / userret 的对称性

                  csrrw a0, sscratch, a0        csrrw a0, sscratch, a0
进入 uservec：                                            ↑
  sscratch = TRAPFRAME      uservec               userret     sscratch = TRAPFRAME
  a0 = 用户 a0                 │                        │          a0 = 用户 a0
                               │ 保存 31 寄存器          │ 恢复 31 寄存器
                               │ 读取 sscratch→a0[112]   │ 写入 a0[112]→sscratch
                               │ 加载内核栈/页表/入口     │ 切换用户页表
                               │ 切换内核页表             │ sret
                               ↓                        │
                          usertrap()            usertrapret() → 调用 userret

进入（uservec）和返回（userret）之间，sscratch 的值形成一个”旋转”：

  • uservec 开始：sscratch = TRAPFRAME，a0 = 用户 a0
  • uservec 结束：sscratch = 用户 a0（通过 csrrw 交换后，csrr t0, sscratch 读出）
  • userret 开始：sscratch = 用户 a0（通过 csrw sscratch, t0 写入）
  • userret 结束：sscratch = TRAPFRAME（通过最后的 csrrw 写回）

下次 uservec 再次执行时，sscratch 又是 TRAPFRAME——循环结构。

三、源码精读：kernel/trap.c 用户态处理部分

3.1 usertrap()——判断 trap 类型并分发

void
usertrap(void)
{
  int which_dev = 0;

  // ① 安全检查：必须来自用户态（SPP 应该等于 0）
  if((r_sstatus() & SSTATUS_SPP) != 0)
    panic("usertrap: not from user mode");

  // ② 立即重定向 stvec 到 kernelvec
  // 现在我们在内核中运行，如果再发生 trap 应该去 kerneltrap()，不是 uservec
  w_stvec((uint64)kernelvec);

  struct proc *p = myproc();
  
  // ③ 保存用户程序计数器（sepc 是"被打断的指令"地址）
  // 必须在开中断之前保存！因为后续中断会覆盖 sepc
  p->trapframe->epc = r_sepc();
  
  if(r_scause() == 8) {
    // ④-A 系统调用（ecall 的 scause = 8）
    
    if(p->killed)
      exit(-1);

    // ecall 的 sepc 指向 ecall 指令本身
    // 系统调用返回后应该执行 ecall 的下一条指令
    p->trapframe->epc += 4;

    // 系统调用处理期间可以开中断（允许抢占）
    intr_on();

    syscall();  // 分发到具体的系统调用处理函数

  } else if((which_dev = devintr()) != 0) {
    // ④-B 中断（时钟、UART、VIRTIO 等）
    // devintr() 已经处理好了，which_dev = 1（外部中断）或 2（时钟中断）

  } else {
    // ④-C 异常（非法指令、页错误等）
    printf("usertrap(): unexpected scause %p pid=%d\n", r_scause(), p->pid);
    printf("            sepc=%p stval=%p\n", r_sepc(), r_stval());
    p->killed = 1;  // 标记进程为"该死"
  }

  // ⑤ 如果进程被杀死，立刻退出
  if(p->killed)
    exit(-1);

  // ⑥ 时钟中断：让出 CPU
  if(which_dev == 2)
    yield();

  // ⑦ 返回用户态
  usertrapret();
}

p->trapframe->epc += 4 的原因：

ecall 指令触发 trap 时，硬件将 sepc 设为 ecall 指令的地址（不是下一条指令）。如果直接用 sepc 来返回，用户程序会再次执行 ecall，导致无限循环！+4 是因为 RISC-V 指令是 32 位（4 字节），ecall 之后的下一条指令在 epc+4 处。

（注意：RISC-V 的压缩指令是 16 位，但 ecall 没有压缩版本，始终是 4 字节。）

w_stvec((uint64)kernelvec) 的时机：

uservec 被调用时，stvec 仍然指向 TRAMPOLINE+uservec_offset（因为在用户态时 stvec 就是这个值）。进入内核后，如果此时发生嵌套 trap（例如系统调用处理期间时钟中断），应该走 kernelvec（内核态 trap 处理），而不是再走 uservec（那会尝试保存到 trapframe 并切换页表，是错误的）。所以 usertrap() 的第一件事就是重设 stvec。

p->trapframe->epc = r_sepc() 必须在 intr_on() 之前：

sepc 是 CSR，在下一次发生任何 trap 时会被硬件覆盖。如果在保存 sepc 之前就开中断（intr_on()），时钟中断到来会覆盖 sepc，用户 PC 就丢失了。所以先把 sepc 保存到 trapframe->epc（内存中，不会被硬件覆盖），然后才能开中断。

3.2 usertrapret()——设置 CSR，返回用户态

（代码已在 2.2 节中详细解读，此处总结关键设计点）

usertrapret() 的工作清单：

1. intr_off()                    关中断，避免在修改 stvec/sstatus/sepc 期间被打断
2. w_stvec(TRAMPOLINE+uservec)   设置用户态 trap 入口（指向 trampoline.S 中的 uservec）
3. 写 trapframe 的内核字段        为下次 trap 进内核做准备（kernel_satp/sp/trap/hartid）
4. sstatus: SPP=0, SPIE=1        设置 sret 后的特权级（User）和中断状态（开启）
5. w_sepc(trapframe->epc)        设置 sret 后的用户 PC
6. 计算用户页表 satp              MAKE_SATP(p->pagetable)
7. 调用 userret(TRAPFRAME, satp) 跳入 trampoline.S/userret，最终 sret 回用户态

四、完整的用户态 Trap 流程图

4.1 用户态进内核（以系统调用为例）

用户程序执行 write(fd, buf, n)：
  user/usys.S: li a7, SYS_write → ecall

硬件（RISC-V CPU）：
  sepc = ecall 指令的地址
  scause = 8（用户态 ecall）
  sstatus.SPP = 0（来自用户态）
  sstatus.SIE = 0（关中断）
  切换到 Supervisor 特权级
  PC = stvec = TRAMPOLINE + uservec 偏移
  （页表不变，仍是用户页表！）

trampoline.S uservec（用户页表 + TRAMPOLINE 虚拟地址）：
  csrrw a0, sscratch, a0       → a0 = TRAPFRAME
  sd ra, 40(a0) ... sd t6, 280(a0)  → 保存 31 个用户寄存器
  csrr t0, sscratch; sd t0, 112(a0) → 保存用户 a0
  ld sp, 8(a0)                 → 加载内核栈
  ld tp, 32(a0)                → 加载 hartid
  ld t0, 16(a0)                → t0 = usertrap() 地址
  ld t1, 0(a0)                 → t1 = 内核页表 satp
  csrw satp, t1                → 切换到内核页表！
  sfence.vma                   → 刷新 TLB
  jr t0                        → 跳入 usertrap()

kernel/trap.c usertrap()：
  SPP 检查
  w_stvec(kernelvec)            → 重定向到内核 trap 处理
  p->trapframe->epc = r_sepc()  → 保存用户 PC
  if scause == 8:               → 是系统调用
    epc += 4                    → 返回 ecall 的下一条指令
    intr_on()                   → 系统调用期间可以开中断
    syscall()                   → 分发到 sys_write()

sys_write() 执行完毕，返回到 usertrap()

kernel/trap.c usertrap()（续）：
  killed 检查
  时钟中断检查（yield）
  usertrapret()

kernel/trap.c usertrapret()：
  intr_off()
  w_stvec(TRAMPOLINE+uservec)   → 重设用户态 trap 入口
  写 trapframe 的 kernel_* 字段  → 下次 trap 进内核的准备
  sstatus: SPP=0, SPIE=1
  w_sepc(trapframe->epc)        → 设置返回 PC
  fn = TRAMPOLINE + userret 偏移
  调用 fn(TRAPFRAME, satp)      → 跳入 userret

trampoline.S userret：
  csrw satp, a1                 → 切换回用户页表！
  sfence.vma                    → 刷新 TLB
  csrw sscratch, (trapframe->a0)→ 下次 uservec 用
  ld ra, 40(a0) ... ld t6, 280(a0)  → 恢复 31 个用户寄存器
  csrrw a0, sscratch, a0        → 恢复 a0，保存 TRAPFRAME→sscratch
  sret                          → 返回用户态，PC = sepc，开中断

用户程序从 ecall 下一条指令继续执行
（a0 = sys_write() 的返回值）

struct trapframe（每进程独占一页 4KB，映射在 TRAPFRAME = TRAMPOLINE - PGSIZE）：

偏移    字段           谁写入        谁读取
  0    kernel_satp    usertrapret() uservec（ld t1, 0(a0)）
  8    kernel_sp      usertrapret() uservec（ld sp, 8(a0)）
 16    kernel_trap    usertrapret() uservec（ld t0, 16(a0)）
 24    epc            usertrap()    usertrapret(): w_sepc()
                      uservec(通过 sepc CSR 的值间接) 
 32    kernel_hartid  usertrapret() uservec（ld tp, 32(a0)）
 40    ra             uservec       userret
 48    sp             uservec       userret
 56    gp             uservec       userret
 64    tp             uservec       userret
 72    t0             uservec       userret
 80    t1             uservec       userret
 88    t2             uservec       userret
 96    s0             uservec       userret
104    s1             uservec       userret

五、TRAMPOLINE 设计的完整推导

5.1 为什么必须同时映射在两个页表且虚拟地址相同？

情景模拟：假设 trampoline 代码在内核页表中映射为 0xC0001000，
          在用户页表中没有映射。

用户态 trap 发生：
  CPU 跳到 stvec（必须在用户页表中可访问）
  → 但 0xC0001000 在用户页表中不存在
  → 立刻产生 Page Fault
  → stvec 又指向 trampoline...
  → 无限页错误，系统崩溃

情景模拟：假设 trampoline 在用户页表中映射为 0x1000，
          在内核页表中映射为 0xC0001000。

执行 uservec（在用户页表中，虚拟地址 0x1000）：
  ...
  csrw satp, t1        → 切换到内核页表
  sfence.vma
  jr t0                → 但 t0 是从 trapframe->kernel_trap 加载的，
                          指向内核页表中的 usertrap() 地址

  ...下一条要执行的 PC 是什么？
  PC 仍然是 0x1000+offset（切换 satp 时 PC 不变）
  但在内核页表中，0x1000 没有 trampoline 的映射（映射在 0xC0001000）
  → Page Fault，系统崩溃

两个页表都映射 TRAMPOLINE 到相同虚拟地址（MAXVA-PGSIZE）：
  切换 satp 后，PC 还是 TRAMPOLINE+offset
  在新页表（内核页表）中，TRAMPOLINE 仍然映射到同一物理页
  → 代码继续正常执行 ✓
  → 然后 jr t0 跳到 usertrap()，进入完全的内核环境

5.2 TRAMPOLINE 的权限设置

// kernel/vm.c kvminit()——内核页表中：
kvmap(kpgtbl, TRAMPOLINE, (uint64)trampoline, PGSIZE, PTE_R | PTE_X);
//                                                         没有 PTE_U！

// kernel/proc.c proc_pagetable()——用户页表中：
mappages(pagetable, TRAMPOLINE, PGSIZE,
         (uint64)trampoline, PTE_R | PTE_X);
//                                    没有 PTE_U！

TRAMPOLINE 没有 PTE_U 标志：用户程序不能执行 trampoline 代码——只有当特权级切换到 Supervisor 时（trap 入口、trap 返回期间），才能访问 TRAMPOLINE 页。如果 PTE_U 置位，恶意用户程序可以跳入 trampoline 代码直接操作内核页表，造成严重安全漏洞。

类似地，TRAPFRAME 也没有 PTE_U：用户程序不能读取或修改自己的 trapframe（否则可以伪造保存的寄存器值，绕过内核的安全检查）。

七、思考题

  1. uservec 为什么不能直接将 TRAPFRAME 地址硬编码在代码中（如 li a0, 0x3ffffe000），而必须通过 sscratch 来获取？

    理论上 TRAPFRAME 地址是固定的（TRAMPOLINE - PGSIZE = 0x3ffffe000），可以硬编码。但 xv6 通过 sscratch 传递是更通用的设计：在支持 COW fork 或其他优化的系统中，trapframe 可能不在固定地址。此外，sscratch 的值在 usertrapret() 时由内核设置，如果将来 trapframe 的位置需要改变，只需修改 usertrapret()，而不必修改汇编代码。更重要的是，csrrw 实现了原子交换——在保存 a0 之前，不需要借用任何其他通用寄存器（所有寄存器都有用户的值，不能破坏任何一个）。

  2. 为什么 TRAMPOLINE 映射时不设置 PTE_U，而 TRAPFRAME 也不设置 PTE_U？如果恶意用户程序直接跳转到 TRAMPOLINE 地址执行 uservec，会发生什么？

    Supervisor 模式执行 uservec 时，sscratch 已经由内核预设为 TRAPFRAME 地址，不受用户控制。但如果 PTE_U 被设置，用户程序可以在用户态执行 TRAMPOLINE 代码：此时特权级是 User，sscratch 的值不受内核控制（用户可以通过之前的 csrw 设置为任意值）。uservec 会将 sscratch 的值作为”TRAPFRAME 地址”，执行一系列 sd 操作——等于将用户寄存器写入用户控制的任意物理地址，可以破坏内核数据。去掉 PTE_U 后，用户态访问这两个页会触发 Page Fault，安全。

  3. usertrapret() 在调用 userret 时传递了两个参数：TRAPFRAME 和 satp。但 userret 是汇编，运行在 TRAMPOLINE 物理页上。为什么第一行执行 csrw satp, a1 之后，代码可以继续在 TRAMPOLINE 虚拟地址运行？

    csrw satp, a1 将 satp 切换到用户页表。切换发生时，PC 仍然指向 TRAMPOLINE 虚拟地址范围内。TRAMPOLINE 页在用户页表中也映射到完全相同的虚拟地址（MAXVA - PGSIZE）且指向相同的物理页——所以切换 satp 后，CPU 用新的（用户）页表翻译 TRAMPOLINE 地址，得到的物理地址与内核页表下相同，代码继续执行。这正是”TRAMPOLINE 必须在两个页表中映射到相同虚拟地址”设计的根本原因。

  4. usertrap() 收到时钟中断时，会调用 yield()->sched()->swtch()，然后切换到调度器。但 yield() 返回后仍然会执行 usertrapret() 返回用户态——这中间进程可能已经被另一个时钟中断打断并重新调度。为什么这不会出问题？

    yield() 返回时，进程重新拥有 CPU。由于 yield() 只是让出然后被重新调度，进程的内核状态（栈、寄存器等）完好无损——swtch() 保证了上下文的完整性。p->trapframe->epc 在 usertrap() 开头就保存好了（调用 yield() 之前），usertrapret() 会用这个值设置 sepc 并返回用户态。整个过程就像进程短暂”休眠”了一会儿，然后从相同的状态继续——用户程序无感知。

  5. RISC-V 有一个 sscratch 寄存器，但没有类似”用于保存 sp”的专用寄存器。uservec 切换到内核栈是通过 ld sp, 8(a0) 完成的——此时 a0 已经指向 TRAPFRAME，trapframe+8 = kernel_sp。问题：如果在执行 ld sp, 8(a0) 之前，用户程序的 sp 非法（如 sp=0），会有什么问题？

    在 ld sp, 8(a0) 之前，sp 仍然是用户态的值。执行这行之前的所有 sd 指令用的是用户的 sp（sd ra, 40(a0) 等都是相对于 a0 寻址，不依赖 sp）。a0 指向 TRAPFRAME（虚拟地址 0x3ffffe000），这个地址在用户页表中是内核通过 proc_pagetable() 预先映射的，是合法的。所以即使用户的 sp = 0，uservec 的 sd 操作不会出错（它们不依赖 sp）。的确问题存在的点是：如果 a0（trapframe 地址）因为某种原因无效，第一个 sd 就会页错误——但 TRAPFRAME 地址来自 sscratch，由内核在 usertrapret() 设置，不受用户控制，所以这是安全的。

  6. trampoline.S 运行时几乎没有依赖——不需要 C 运行时、不需要全局变量、不能调用任何 C 函数。这是为什么？如果想在 uservec 中调用一个 C 函数（如打印日志），在何时才安全？

    uservec 执行时处于极端约束环境：(1) 用户页表——无法访问内核的数据段、BSS、全局变量；(2) 无内核栈（用户 sp 可能无效）——无法调用任何需要栈的函数；(3) satp 随时可能是用户页表或刚切换后的内核页表。任何 C 函数调用都需要：有效的 sp、正确的页表（访问代码和数据）、可能还需要内核的 BSS/数据段。这一切在 ld sp, 8(a0) 加载内核栈、csrw satp, t1 切换内核页表、并且 sfence.vma 刷新 TLB 之后才具备。所以，安全调用 C 函数的最早时机是 jr t0（即 usertrap() 的入口）——这正是 xv6 的做法：汇编只做最小化工作（保存寄存器、切换页表和栈），然后立刻跳入 C 函数。

八、本节小结

概念 要点
Trap 三种来源 syscall（ecall, scause=8）、异常（非法访问等）、中断（时钟、外设）
硬件 trap 时做的事 sepc←PC, scause←原因, SPP←特权级, 关中断, 跳到 stvec（不切页表！）
TRAMPOLINE 设计 同一物理页映射到两个页表的相同虚拟地址，无 PTE_U，保证切换 satp 时代码连续
TRAPFRAME 设计 每进程独占一页（TRAMPOLINE-PGSIZE），存放 32 个用户寄存器 + 5 个内核字段
csrrw 技巧 原子交换 a0 和 sscratch：无需借用寄存器即可获得 TRAPFRAME 地址
uservec 步骤 交换 a0/sscratch → 保存 31 寄存器 → 保存 a0 → 加载内核栈/hartid/usertrap → 切换 satp → 跳入 usertrap()
usertrap() 步骤 检查 SPP → 重设 stvec → 保存 sepc → 分发（syscall/中断/异常）→ 检查 killed → 可能 yield → usertrapret()
usertrapret() 步骤 关中断 → 设 stvec → 写 trapframe 内核字段 → 设 sstatus/sepc → 调用 userret
userret 步骤 切换用户页表 → 设 sscratch → 恢复 31 寄存器 → csrrw 恢复 a0/保存 TRAPFRAME → sret
epc += 4 ecall 的 sepc 指向 ecall 自身，需 +4 跳过，否则系统调用返回后无限循环
中断开关时机 保存 sepc 之前不能开中断；usertrapret() 一开始关中断防止修改 CSR 时被打断

下一节预告：第 10 节将聚焦系统调用的完整实现——usys.S 自动生成的 stub、syscall() 分发表、argint()/argaddr()/argstr() 如何安全地从用户空间取参数，以及如何向 xv6 添加一个全新的系统调用。
