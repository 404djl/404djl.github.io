第17节：字符设备驱动（UART 与 Console）

学习目标

  • 理解 MMIO（内存映射 I/O）与 16550A UART 寄存器的交互方式
  • 掌握中断驱动 I/O 的设计：发送侧的异步缓冲、接收侧的回调链
  • 理解 console 三索引环形缓冲区的行编辑协议（echo、backspace、Ctrl-U、Ctrl-D）
  • 掌握 PLIC 中断控制器在 xv6 中的角色与路由流程
  • 理解内核 printf 与用户 write 两条不同输出路径

预计用时：3～4 小时
前置要求：第11节（Trap机制/内核态中断）、第16节（文件描述符与系统调用层）、第12节（锁机制）

一、硬件背景：UART 16550A 与 MMIO

1.1 MMIO 基本概念

xv6 运行在 QEMU 模拟的 RISC-V 平台上，外设寄存器通过内存映射 I/O（MMIO） 暴露给 CPU：将外设寄存器映射到某段物理地址，CPU 用普通的内存读写指令（lw/sw）访问外设——无需专用 I/O 指令。

物理地址空间（QEMU virt 平台）：

0x00000000 ── 0x0FFFFFFF   普通 RAM（前 16 MB 保留给机器固件）
0x0C000000                 PLIC（中断控制器）
0x10000000                 UART0（串口，16550A）   ← UART0_IRQ = 10
0x10001000                 VirtIO 磁盘              ← VIRTIO0_IRQ = 1
0x80000000 ──              RAM（xv6 运行区域）

关键宏（kernel/memlayout.h）：

#define UART0      0x10000000L    // UART 寄存器基地址
#define UART0_IRQ  10             // UART 的中断号

1.2 16550A UART 寄存器

16550A 是经典的串行通信芯片，xv6 通过以下寄存器偏移访问它：

// kernel/uart.c 寄存器偏移定义
#define RHR 0    // 接收保持寄存器（读时：读取收到的字节）
#define THR 0    // 发送保持寄存器（写时：发送一个字节）
#define IER 1    // 中断使能寄存器
#define FCR 2    // FIFO 控制寄存器（写）
#define ISR 2    // 中断状态寄存器（读）
#define LCR 3    // 线路控制寄存器（波特率、字长）
#define LSR 5    // 线路状态寄存器

// LSR 状态位
#define LSR_RX_READY (1<<0)   // 位0=1：RHR 中有数据可读
#define LSR_TX_IDLE  (1<<5)   // 位5=1：THR 空闲，可发送

寄存器访问宏：

#define Reg(reg) ((volatile unsigned char *)(UART0 + reg))
#define ReadReg(reg)    (*(Reg(reg)))
#define WriteReg(reg,v) (*(Reg(reg)) = (v))

volatile 关键字告诉编译器不要优化对这些地址的访问——外设状态由硬件改变，不能被缓存。

1.3 PLIC 中断控制器

PLIC（Platform Level Interrupt Controller）负责将多个外设中断路由到 CPU 核心：

外设 UART    (IRQ=10)  ──┐
外设 VirtIO  (IRQ=1)   ──┤──→  PLIC  ──→  CPU hart0/hart1
外设 ...                 ┘          (S 模式外部中断，scause bit63=1, bits=9)

PLIC 寄存器地址（kernel/memlayout.h）：
PLIC            = 0x0C000000   // 中断优先级配置
PLIC_SENABLE(h) = PLIC + 0x2080 + h*0x100   // S 模式中断使能（按 hart）
PLIC_SPRIORITY(h)= PLIC + 0x201000 + h*0x2000  // S 模式优先级阈值
PLIC_SCLAIM(h)  = PLIC + 0x201004 + h*0x2000   // claim/complete 寄存器

中断处理流程：

硬件中断 (e.g. UART 收到字符)
  → PLIC 置 pending 位
  → CPU 进入 S 模式中断，跳转 kernelvec → usertrap/kerneltrap
  → devintr()
      ├── plic_claim()       读 PLIC_SCLAIM 获取 irq 号
      ├── if(irq==UART0_IRQ): uartintr()
      ├── if(irq==VIRTIO0_IRQ): virtio_disk_intr()
      └── plic_complete(irq) 通知 PLIC 处理完毕，允许下次中断

二、uart.c 源码精读

2.1 uartinit — 硬件初始化

void
uartinit(void)
{
  // 1. 先关闭所有中断，再配置参数
  WriteReg(IER, 0x00);

  // 2. 进入波特率设置模式（LCR bit7=1）
  WriteReg(LCR, LCR_BAUD_LATCH);       // LCR_BAUD_LATCH = (1<<7)

  // 3. 设置波特率 38400（除数=3）：LSB=0x03, MSB=0x00
  WriteReg(0, 0x03);    // 除数低字节 → 偏移 0（覆盖 RHR/THR）
  WriteReg(1, 0x00);    // 除数高字节 → 偏移 1（覆盖 IER）

  // 4. 退出波特率模式，设置 8 数据位，无奇偶校验
  WriteReg(LCR, LCR_EIGHT_BITS);       // LCR_EIGHT_BITS = (3<<0) = 0x03

  // 5. 复位并启用 FIFO（16字节收/发缓冲）
  WriteReg(FCR, FCR_FIFO_ENABLE | FCR_FIFO_CLEAR);

  // 6. 使能发送（TX）和接收（RX）中断
  WriteReg(IER, IER_TX_ENABLE | IER_RX_ENABLE);

  initlock(&uart_tx_lock, "uart");
}

波特率计算：16550A 内部时钟为 1.8432 MHz，除数=3 时：波特率 = 1843200 / (16×3) = 38400 bps。

2.2 发送侧：软件缓冲 + 中断驱动

xv6 UART 的发送路径分为两层：

上层（可睡眠）: uartputc(c)
  ─ 将字符存入 uart_tx_buf[32]（环形）
  ─ 调用 uartstart() 尝试发送
  ─ 若缓冲区满，sleep 等待

下层（中断回调）: uartintr() → uartstart()
  ─ 发送队列中所有可发送的字符
  ─ 唤醒等待的 uartputc

发送缓冲区（32字节环形）：

struct spinlock uart_tx_lock;
#define UART_TX_BUF_SIZE 32
char uart_tx_buf[UART_TX_BUF_SIZE];
int uart_tx_w;  // 写指针（下一个写入位置）
int uart_tx_r;  // 读指针（下一个发送位置）

// 缓冲区满：(uart_tx_w + 1) % SIZE == uart_tx_r
// 缓冲区空：uart_tx_w == uart_tx_r

uartputc — 上半部（top half）：

void
uartputc(int c)
{
  acquire(&uart_tx_lock);

  if(panicked){
    for(;;) ;          // panic 后死循环，不再发送
  }

  while(1){
    if(((uart_tx_w + 1) % UART_TX_BUF_SIZE) == uart_tx_r){
      // 缓冲区满：等待 uartstart 消费数据腾出空间
      // sleep 在 &uart_tx_r 上，由 uartstart 唤醒
      sleep(&uart_tx_r, &uart_tx_lock);
    } else {
      uart_tx_buf[uart_tx_w] = c;
      uart_tx_w = (uart_tx_w + 1) % UART_TX_BUF_SIZE;
      uartstart();       // 尝试立即发送
      release(&uart_tx_lock);
      return;
    }
  }
}

uartstart — 发送引擎（需持有 uart_tx_lock）：

void
uartstart()
{
  while(1){
    if(uart_tx_w == uart_tx_r){
      return;             // 缓冲区空，无需发送
    }
    
    if((ReadReg(LSR) & LSR_TX_IDLE) == 0){
      // UART 发送保持寄存器（THR）还未空闲
      // 等待硬件发送完毕后产生 TX 中断再来
      return;
    }
    
    int c = uart_tx_buf[uart_tx_r];
    uart_tx_r = (uart_tx_r + 1) % UART_TX_BUF_SIZE;
    
    wakeup(&uart_tx_r);  // 唤醒可能阻塞在 uartputc 的进程
    
    WriteReg(THR, c);    // 写入 THR，硬件开始发送该字节
  }
}

uartputc_sync — 同步阻塞发送（不使用中断）：

void
uartputc_sync(int c)
{
  push_off();           // 关中断（防止在中断处理中睡眠）

  if(panicked){
    for(;;) ;
  }

  // 忙等：轮询 LSR 直到 THR 空闲
  while((ReadReg(LSR) & LSR_TX_IDLE) == 0)
    ;
  WriteReg(THR, c);     // 直接写入，不经过软件缓冲区

  pop_off();
}

uartputc_sync 用于：

  1. **内核 printf**：可能在持有锁或中断关闭时调用，不能 sleep
  2. 字符回显（echo）：consoleintr 在中断上下文中，不能 sleep

2.3 接收侧

// 非阻塞：检查 RHR 是否有数据
int
uartgetc(void)
{
  if(ReadReg(LSR) & 0x01){
    return ReadReg(RHR);    // 读取字节（清除 RX 中断）
  } else {
    return -1;              // 无数据
  }
}

// UART 中断处理（由 trap.c 的 devintr() 调用）
void
uartintr(void)
{
  // 接收：循环读取所有待处理的输入字符
  while(1){
    int c = uartgetc();
    if(c == -1)
      break;
    consoleintr(c);     // 将字符交给 console 的行编辑处理
  }

  // 发送：利用本次中断机会继续发送缓冲区中的字符
  acquire(&uart_tx_lock);
  uartstart();
  release(&uart_tx_lock);
}

发送 TX 中断的触发条件：当 UART 发送完一个字节、THR 重新空闲时，若 IER 中 TX 中断已使能，UART 会产生中断。这时 uartintr 被调用，再次执行 uartstart()，继续发送队列中的下一个字节。

三、console.c 源码精读

console 是建立在 UART 之上的行导向终端，负责：

  1. 输出：将 write() 系统调用的数据字节逐个送到 uartputc
  2. 输入：从 UART 收集字符，支持行编辑，按行提供给 read() 系统调用

3.1 console 输入缓冲区：三索引设计

struct {
  struct spinlock lock;
  
  #define INPUT_BUF 128
  char buf[INPUT_BUF];    // 128 字节环形缓冲区
  uint r;   // 读索引  (read index)：consoleread 从此处读走字符
  uint w;   // 写索引  (write index)：已完成一行，可供读者消费
  uint e;   // 编辑索引(edit index)：当前正在编辑的位置（含未确认字符）
} cons;

三个索引的关系：

buf[128]:
  r ≤ w ≤ e   (均为单调递增，取模 128 做环形索引)

  [r  ... w)   ← 已确认，等待 consoleread 消费的完整行
  [w  ... e)   ← 正在编辑，尚未按回车确认（用户可退格修改）
  [e  ...  )   ← 空闲

状态图：
  输入 'h','e','l','l','o':    r=0, w=0, e=5  (未确认)
  按下 '\n':                   r=0, w=6, e=6  (wakeup consoleread)
  consoleread 读完:             r=6, w=6, e=6

相比两索引方案（只有 r 和 w），三索引允许在确认（换行/Ctrl-D）前随时退格撤销，而不影响已确认行的读取。

3.2 consoleintr — 中断处理（下半部）

void
consoleintr(int c)
{
  acquire(&cons.lock);

  switch(c){
  case C('P'):        // Ctrl-P：打印所有进程（调试用）
    procdump();
    break;

  case C('U'):        // Ctrl-U：删除整行（Kill Line）
    // 从当前编辑位置向前，逐字符退格，直到回到行首或换行符
    while(cons.e != cons.w &&
          cons.buf[(cons.e-1) % INPUT_BUF] != '\n'){
      cons.e--;
      consputc(BACKSPACE);    // 发送退格序列到终端
    }
    break;

  case C('H'):        // Ctrl-H（0x08）：退格
  case '\x7f':        // DEL（0x7F）：退格（部分终端）
    if(cons.e != cons.w){    // 保证不越界到已确认区域
      cons.e--;
      consputc(BACKSPACE);
    }
    break;

  default:
    if(c != 0 && cons.e - cons.r < INPUT_BUF){
      // 普通字符：将 \r 转换为 \n
      c = (c == '\r') ? '\n' : c;

      consputc(c);            // 立即回显（echo back）

      cons.buf[cons.e++ % INPUT_BUF] = c;   // 存入编辑区

      // 满足以下任一条件时，将 w 推进到 e，唤醒 consoleread：
      // 1. 收到换行符 → 一行结束
      // 2. 收到 Ctrl-D → EOF
      // 3. 缓冲区满（防止溢出）
      if(c == '\n' || c == C('D') || cons.e == cons.r + INPUT_BUF){
        cons.w = cons.e;
        wakeup(&cons.r);      // 唤醒等待读取的进程
      }
    }
    break;
  }
  
  release(&cons.lock);
}

consputc — 回显输出（在 consoleintr 中调用，不能 sleep）：

void
consputc(int c)
{
  if(c == BACKSPACE){
    // 退格视觉效果：'\b'（向左移1格）+ ' '（覆盖字符）+ '\b'（再向左）
    uartputc_sync('\b');
    uartputc_sync(' ');
    uartputc_sync('\b');
  } else {
    uartputc_sync(c);    // 直接同步发送（中断上下文，不能 sleep）
  }
}

3.3 consoleread — 用户读（上半部）

int
consoleread(int user_dst, uint64 dst, int n)
{
  uint target = n;       // 记录目标字节数（用于计算返回值）
  int c;
  char cbuf;

  acquire(&cons.lock);
  while(n > 0){
    // 等待：直到 consoleintr 将 w 推进（即有确认行可读）
    while(cons.r == cons.w){
      if(myproc()->killed){
        release(&cons.lock);
        return -1;
      }
      sleep(&cons.r, &cons.lock);   // 在 cons.r 上睡眠
    }

    c = cons.buf[cons.r++ % INPUT_BUF];   // 消费一字节

    if(c == C('D')){    // Ctrl-D = EOF
      if(n < target){
        // 本次 read 已经读了一些字符，需要保留 ^D 供下次 read 返回 0
        cons.r--;       // 把 Ctrl-D 放回，下次 read 会返回 0
      }
      break;
    }

    cbuf = c;
    if(either_copyout(user_dst, dst, &cbuf, 1) == -1)
      break;

    dst++;
    --n;

    if(c == '\n'){
      break;           // 一次 read 最多消费一行
    }
  }
  release(&cons.lock);

  return target - n;   // 实际读取的字节数
}

3.4 consolewrite — 用户写

int
consolewrite(int user_src, uint64 src, int n)
{
  int i;

  acquire(&cons.lock);
  for(i = 0; i < n; i++){
    char c;
    if(either_copyin(&c, user_src, src+i, 1) == -1)
      break;
    uartputc(c);    // 异步发送（使用 tx 缓冲区，可 sleep）
  }
  release(&cons.lock);

  return i;
}

注意：consolewrite 用 uartputc（可睡眠，走软件缓冲区），而 consputc（回显）用 uartputc_sync（不可睡眠，忙等）。

3.5 consoleinit — 注册设备

void
consoleinit(void)
{
  initlock(&cons.lock, "cons");
  uartinit();                          // 初始化 UART 硬件

  // 将 console 读写函数注册到设备函数表
  devsw[CONSOLE].read  = consoleread;
  devsw[CONSOLE].write = consolewrite;
}

此后，对 /dev/console（设备号 major=1）的 read/write 系统调用会经由 fileread/filewrite → devsw[1].read/write 路由到这里。

四、printf.c 源码精读

4.1 内核 printf

volatile int panicked = 0;   // panic 后置 1，让其他 CPU 的 uartstart 停止

static struct {
  struct spinlock lock;
  int locking;               // 初始为 0，printfinit 后置 1
} pr;

void
printf(char *fmt, ...)
{
  va_list ap;
  int i, c, locking;
  char *s;

  locking = pr.locking;
  if(locking)
    acquire(&pr.lock);       // 防止多 CPU 并发 printf 输出乱码

  if(fmt == 0)
    panic("null fmt");

  va_start(ap, fmt);
  for(i = 0; (c = fmt[i] & 0xff) != 0; i++){
    if(c != '%'){
      consputc(c);           // 普通字符：直接调用 consputc（同步）
      continue;
    }
    c = fmt[++i] & 0xff;
    switch(c){
    case 'd': printint(va_arg(ap, int), 10, 1); break;   // 十进制整数
    case 'x': printint(va_arg(ap, int), 16, 1); break;   // 十六进制整数
    case 'p': printptr(va_arg(ap, uint64));     break;   // 指针（0x...）
    case 's':
      s = va_arg(ap, char*);
      if(s == 0) s = "(null)";
      for(; *s; s++) consputc(*s);
      break;
    case '%': consputc('%'); break;
    default:
      consputc('%');
      consputc(c);           // 未知格式符：原样输出
    }
  }

  if(locking)
    release(&pr.lock);
}

支持的格式符：仅 %d、%x、%p、%s，比标准 C 库简单得多，够内核调试使用即可。

4.2 panic — 内核崩溃处理

void
panic(char *s)
{
  pr.locking = 0;      // 关闭 printf 锁（避免死锁，直接输出）
  printf("panic: ");
  printf(s);
  printf("\n");
  panicked = 1;        // 通知其他 CPU：系统已崩溃
  for(;;)              // 当前 CPU 死循环（halt）
    ;
}

panicked = 1 之后，uartputc 和 uartputc_sync 都会检测到这个标志并死循环，防止其他 CPU 继续发送，冻结终端输出方便调试。

4.3 printint / printptr 实现原理

static void
printint(int xx, int base, int sign)
{
  char buf[16];     // 最多 16 位（二进制最长）
  int i;
  uint x;

  if(sign && (sign = xx < 0))
    x = -xx;        // 处理负数
  else
    x = xx;

  i = 0;
  do {
    buf[i++] = digits[x % base];   // 低位先存（逆序）
  } while((x /= base) != 0);

  if(sign)
    buf[i++] = '-';

  while(--i >= 0)
    consputc(buf[i]);   // 逆序输出 = 正确顺序
}

static void
printptr(uint64 x)
{
  int i;
  consputc('0'); consputc('x');     // 固定前缀 "0x"
  // 从最高 4 位开始（64位 = 16个十六进制位）
  for(i = 0; i < (sizeof(uint64) * 2); i++, x <<= 4)
    consputc(digits[x >> (sizeof(uint64) * 8 - 4)]);
}

五、完整 I/O 路径图

5.1 键盘输入路径（用户进程 read）

物理键盘按键
  → QEMU 串口仿真
  → UART 硬件：字节存入 RHR，置 LSR_RX_READY，向 PLIC 发送 IRQ=10
  → PLIC：向 CPU hart 发送外部中断
  → CPU：进入 S 模式中断，跳转 kernelvec → usertrap/kerneltrap
  → devintr()
      ├── plic_claim()    → 返回 irq=10
      ├── uartintr()
      │   ├── uartgetc()          读 RHR 取字节 c
      │   └── consoleintr(c)
      │       ├── 普通字符：存入 cons.buf[e++], consputc(回显)
      │       ├── \n / Ctrl-D：cons.w = cons.e; wakeup(&cons.r)
      │       └── Ctrl-H / DEL：cons.e--; consputc(BACKSPACE)
      └── plic_complete(10)
  → 若用户进程在 consoleread → sleep(&cons.r) 中等待：
      wakeup 唤醒它
  → consoleread：从 cons.buf[r++] 读字节，copyout 到用户空间
  → sys_read → fileread → consoleread → 返回字节数
  → 用户进程获得输入

5.2 用户程序 write 到屏幕路径

用户程序: write(1, buf, n)
  → ecall → usertrap → sys_write
  → filewrite(f, addr, n)      f->type = FD_DEVICE, f->major = CONSOLE
  → devsw[CONSOLE].write(1, addr, n)
  → consolewrite(user_src=1, src=addr, n)
      └── 逐字节: either_copyin 读取 → uartputc(c)
  → uartputc: 存入 uart_tx_buf[w++], 调用 uartstart()
  → uartstart: 若 THR 空闲，WriteReg(THR, c)
  → UART 硬件:发送字节到串口
  → QEMU → 终端显示字符

5.3 内核 printf 路径

内核代码: printf("hello %d\n", 42)
  → printf → consputc(c)          （跳过 uartputc，直接同步）
  → uartputc_sync(c)
      ├── push_off()              关中断
      ├── while(!(LSR & TX_IDLE)) 忙等
      ├── WriteReg(THR, c)        直接写硬件
      └── pop_off()
  → UART 硬件发送

两条路径对比：

路径 函数 阻塞方式 适用场景
用户 write uartputc sleep（可调度） 正常 I/O，有进程上下文
内核 printf / echo uartputc_sync 忙等（busy-wait） 中断上下文、panic、调试

六、启动顺序中的 Console/UART 初始化

// kernel/main.c（CPU 0 启动流程节选）
void
main()
{
  if(cpuid() == 0){
    consoleinit();    // 1. 初始化 cons 锁 + uartinit + 注册 devsw
    printfinit();     // 2. 初始化 pr 锁，开启 printf 锁保护
    printf("\n");
    printf("xv6 kernel is booting\n");
    printf("\n");
    // ... 其他初始化（kinit, kvminit, procinit, ...）
  }
}

初始化顺序的约束：

  • consoleinit 必须在任何 printf 之前（否则 consputc 输出到未初始化的 UART）
  • printfinit 之前，printf 不加锁（pr.locking=0）——这期间 printf 不是线程安全的，但 CPU 0 启动时其他 CPU 还未运行，安全

七、devsw 设备抽象全景

consoleinit() 注册后：

devsw[0]    = { NULL, NULL }           // 未使用
devsw[1]    = { consoleread,           // CONSOLE (major=1)
                consolewrite }
devsw[2..9] = { NULL, NULL }           // 保留

调用路径：
  fileread(f, addr, n)  when f->type == FD_DEVICE
    → devsw[f->major].read(1, addr, n)
    → consoleread(1, addr, n)

  filewrite(f, addr, n) when f->type == FD_DEVICE
    → devsw[f->major].write(1, addr, n)
    → consolewrite(1, addr, n)

新增设备（如网卡）只需：

  1. 分配一个主设备号
  2. 实现 read/write 函数
  3. 在初始化时注册 devsw[major]
  4. 用 mknod 创建设备文件

八、动手实验

实验一：追踪 UART 寄存器操作

在 kernel/uart.c 的 WriteReg 宏展开处添加调试输出（仅在初始化时打印），观察波特率配置序列：

// 临时修改 uartinit，初始化完成后打印
void
uartinit(void)
{
  WriteReg(IER, 0x00);
  // ... 其他寄存器配置 ...
  WriteReg(IER, IER_TX_ENABLE | IER_RX_ENABLE);
  initlock(&uart_tx_lock, "uart");
  // 注意：此时 printf 尚未初始化，使用 uartputc_sync
  // 实际调试时可在 printfinit 后加 printf("uart ready\n");
}

实验二：观察 console 三索引变化

在 consoleintr 中添加调试打印，实时观察 r/w/e 三个索引的变化：

// 在 consoleintr 函数末尾、release 之前插入
printf("  [cons] r=%d w=%d e=%d\n", cons.r, cons.w, cons.e);

运行 xv6 后输入 "ab" 再按退格，再输入 "c<enter>"，会看到类似：

  [cons] r=0 w=0 e=1     (输入 'a')
  [cons] r=0 w=0 e=2     (输入 'b')
  [cons] r=0 w=0 e=1     (退格)
  [cons] r=0 w=0 e=2     (输入 'c')
  [cons] r=0 w=3 e=3     (按回车，w 推进，wakeup)

实验三：实现 Ctrl-L 清屏功能

在 consoleintr 的 switch 中添加一个新的 case：

case C('L'):   // Ctrl-L：清屏（发送 ANSI 清屏序列）
  // ANSI 转义序列 ESC[2J 清屏，ESC[H 移光标到左上角
  consputc('\033'); consputc('['); consputc('2'); consputc('J');
  consputc('\033'); consputc('['); consputc('H');
  break;

重新编译运行，在 xv6 shell 中按 Ctrl-L 会清屏。

实验四：分析 panic 停机机制

在 xv6 内核中主动触发 panic：

// 在 kernel/main.c 的某处临时添加：
panic("test panic");

观察：

  1. panic 输出 “panic: test panic” 后死循环
  2. 其他 CPU 的 uartputc 检测到 panicked=1 后也死循环
  3. QEMU 终端输出冻结

分析为什么 panicked 用 volatile int 而不是普通 int：防止编译器缓存该值，确保各 CPU 实时读取内存中的最新状态。

实验五：添加新字符设备

实现一个简单的随机数设备 /dev/rand（返回伪随机字节）：

// kernel/rand.c（新建）
#include "types.h"
#include "riscv.h"
#include "defs.h"
#include "file.h"

static uint64 seed = 12345678;

int
randread(int user_dst, uint64 dst, int n)
{
  for(int i = 0; i < n; i++){
    seed = seed * 6364136223846793005ULL + 1442695040888963407ULL;
    char c = (char)(seed >> 33);
    if(copyout(myproc()->pagetable, dst+i, &c, 1) < 0)
      return i;
  }
  return n;
}

void
randinit(void)
{
  devsw[2].read = randread;   // 主设备号 2
}

在 main.c 调用 randinit()，然后 mknod /dev/rand 2 0，即可 cat /dev/rand。

九、本节小结

组件 文件 核心作用
UART 寄存器宏 kernel/uart.c MMIO 访问 16550A（RHR/THR/LCR/LSR/IER/FCR）
uartinit kernel/uart.c 配置波特率/字长/FIFO，使能中断
uartputc kernel/uart.c 异步发送（软件 32 字节环形缓冲 + sleep）
uartputc_sync kernel/uart.c 同步忙等发送（适用中断上下文/panic）
uartstart kernel/uart.c 发送引擎，将缓冲字节写入 THR
uartgetc kernel/uart.c 非阻塞读 RHR
uartintr kernel/uart.c UART 中断处理：接收→consoleintr，发送→uartstart
cons 结构体 kernel/console.c 128 字节三索引环形缓冲（r/w/e）
consoleintr kernel/console.c 键盘输入处理：echo + 行编辑（退格/Ctrl-U/Ctrl-D）
consoleread kernel/console.c 用户 read 实现：按行阻塞读取
consolewrite kernel/console.c 用户 write 实现：逐字节调用 uartputc
consoleinit kernel/console.c 注册 devsw[CONSOLE]
printf kernel/printf.c 内核格式化输出（%d/%x/%p/%s）
panic kernel/printf.c 内核崩溃：输出信息 + 冻结系统
PLIC + devintr kernel/plic.c + trap.c 外部中断路由：irq=10→uartintr

核心设计思想：

  1. 上下半部分离（Top/Bottom Half）：uartputc（上，可 sleep）与 uartintr→uartstart（下，中断，不可 sleep）通过共享环形缓冲区协作
  2. 三索引行编辑：r≤w≤e 优雅地分离”已消费/可读/正编辑”三个状态，支持行内修改而不影响已完成行
  3. 两条 printf 路径：用户 write 走异步路径（高效），内核 printf 走同步忙等路径（安全）
  4. devsw 多态：字符设备通过函数指针表实现统一接口，新设备只需注册无需修改框架代码
  5. volatile + panicked：跨 CPU 的简单同步，不使用锁（panic 时锁状态不可信）
